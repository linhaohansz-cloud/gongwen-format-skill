# 国企公文格式规范（GB/T 9704 类党政机关公文）

> 本规范为「国企公文格式」skill 的权威格式依据，与用户提供的标准版模板 100% 一致。
> 生成时**复制标准版模板 → 仅替换正文**，从而 100% 继承页面设置与页脚页码；
> 不得自行更改任何字体、字号、边距、行距、结构。

## 1. 标准版模板（权威来源）
- 默认参考路径：`C:\Users\AW\OneDrive\codex\codex公文格式\公文格式标准版.docx`
- 特征：采用**直接格式**（每个 run/paragraph 自带 rPr/pPr，不引用 pStyle）。
- 方法：复制模板 zip → 仅替换 `word/document.xml` 的 body 内 `<w:p>` → 保留末位 `<w:sectPr>` 与页脚引用 → 重新打包。

## 2. 页面设置（sectPr / w:pgMar，单位 twips，1 inch = 1440 twips）
| 参数 | 值 | 换算 |
|------|-----|------|
| 纸张 | A4 (210×297mm) | — |
| 上边距 | 2098 | 37mm |
| 下边距 | 1984 | 35mm |
| 左边距 | 1531 | 27mm |
| 右边距 | 1531 | 27mm |
| 页眉 | 850 | 约 15mm (1.5cm) |
| 页脚 | 1531 | 27mm (2.7cm) |
| gutter | 0 | — |

**版心**：标准每页 **22 行 × 26 字**；可增减 1–2 行但要调整行距、**保持版心高度不变**。

## 3. 字体 / 字号 / 对齐 / 缩进（sz 单位为 half-point，`sz=44`=22pt=二号）
| 元素 | 字体 | sz | 字号 | 对齐 | 首行缩进 | 加粗 | 备注 |
|------|------|-----|------|------|----------|------|------|
| 标题（可两行） | 方正小标宋简体 | 44 | 二号 | 居中 | 无 | **否**（非粗体） | 倒梯形排布，第一行最长 |
| 日期副标题 | 楷体_GB2312 | 32 | 三号 | 居中 | 无 | 否 | 例：`(2026 年 08 月 16 日)` |
| 空行 | （无 run） | — | — | — | — | — | keepNext + line=560 exact，无文字 |
| 主送单位 | 仿宋_GB2312 | 32 | 三号 | 左对齐 | 无 | 否 | 例：`主送单位：市体育局` |
| 正文 body | 仿宋_GB2312 | 32 | 三号 | 两端对齐 | firstLine=640（2 字符） | 否 | 含 rSpacing=8 |
| 一级标题 h1 | 黑体 | 32 | 三号 | 左对齐 | 无 | **是**（粗体） | firstLine=0，含 rSpacing=8 |
| 二级标题 h2 | 楷体_GB2312 | 32 | 三号 | 左对齐 | 无 | 否 | firstLine=0，含 rSpacing=8 |
| 三级标题 h3 | 仿宋_GB2312 | 32 | 三号 | 左对齐 | 无 | 否 | firstLine=0，含 rSpacing=8 |

## 4. 行距（统一）
- 所有正文/标题段落：`w:spacing w:line="560" w:lineRule="exact"`（固定 28 磅）。
- 段落 pPr 均带 `<w:keepNext/>`（标题、日期、主送、各级标题、正文一致）。
- 正文段落额外带 `<w:keepLines w:val="0"/>` 与 `<w:widowControl/>`。

## 5. 页脚 / 页码
- 格式：`— PAGE —`（左右各一条一字线，中间页码域）。
- 字体：宋体；`sz=28`（14pt）；`jc` 右对齐；行距14 磅（`line=280 lineRule=exact`）。
- 页码为 `PAGE` 域，不要写死数字。

## 6. 文档结构顺序（必须遵循，含关键空行）
1. 标题（方正小标宋，可拆两行，居中，**倒梯形排布**：第一行最长，逐行递减）
2. 日期副标题（楷体，居中）
3. **空一行**（仅 keepNext + line=560 exact，无文字）—— ⚠️ 日期后必须空一行
4. 主送单位（仿宋，左对齐）
5. 引言/导语正文（仿宋，两端对齐，首行缩进 2 字符）
6. 一级标题（黑体加粗）→ 二级标题（楷体）→ 三级标题（仿宋）→ 正文，按需嵌套
7. 结尾一般无落款/印章区；如用户要求落款再另行处理

## 7. 分页控制
- **小标题尽量不要分页**：二级 `（一）`、三级 `（1）` 等与其引领的正文段应避免被分页断开。
- 实现：为各级标题设置 `<w:keepNext/>`，确保标题与紧随其后的正文首段同页。
- 长正文段自然延续至下一页可接受，但避免同一"小点"（标题+其起始正文）被拆开。

## 8. 内容 JSON 约定
```json
[
  ["title",   "关于本月国内体育事业"],
  ["title",   "发展运行情况分析报告"],
  ["date",    "(2026 年 08 月 16 日)"],
  ["zhusong", "主送单位：市体育局、市商务局"],
  ["body",    "引言正文……"],
  ["h1",      "一、全民健身与群众体育开展情况"],
  ["h2",      "（一）健身场地设施供给持续增加"],
  ["body",    "正文……"],
  ["h3",      "（1）夜间体育消费升温"],
  ["body",    "正文……"]
]
```
- `kind ∈ {title, date, zhusong, body, h1, h2, h3}`。
- `title` 每个数组项为一行；多行时按倒梯形排布（首行最长）。
- `date` 之后脚本自动插入空行，无需在 JSON 写空项。
